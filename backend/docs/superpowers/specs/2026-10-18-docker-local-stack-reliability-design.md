# Docker 本地运行、端口与备份设计

> 2026-10-18 审阅结论：端口与固定镜像方向可用，初稿遗漏局域网媒体地址、空机器初始化、完整备份范围。仅改 8088 绑定不能完成可用的局域网访问；以下已补齐必要修改要求。

## 目标

- 将小哈书本地基础设施与 Java/前端服务继续统一由 Compose 管理，已有容器数据不因本次改造被删除或重置。
- 前端只开放 8088 到局域网，网页通过容器网络中的 Nginx 代理访问网关；MySQL、Redis、Cassandra、MinIO、ES、MQ、Nacos、管理台和网关宿主机端口继续限制在本机回环地址。
- Redis Roaring 镜像固定到已验证的不可变镜像 digest，避免 `latest` 在重新部署时变化。
- 将容器数据路径参数化，支持在本机 `F:\docker` 使用并为后续迁移提供明确步骤。
- 为权威业务数据增加可操作的本地备份与恢复说明，并盘点旧的非 Compose 容器；仅移除能明确证明已弃用的单个容器，保留其数据卷。
- 不尝试 FRP 公网/VPS 验证；当前只有本机转发链路，未来有服务器再单独完成。

## 端口与访问

- 前端映射为宿主机 `0.0.0.0:8088`（Docker Compose 简写 `8088:80`），允许同一局域网访问。最终可访问性仍受 Windows 防火墙和网络隔离策略影响。
- 网关映射仍为 `127.0.0.1:8000:8000`。前端 Nginx 在 Compose 网络内通过服务名访问网关，浏览器请求仍使用相对 `/api` 路径。
- MinIO 服务端地址与浏览器访问地址分离：Java 用 `minio:9000`，上传结果使用同源 `/media/xiaohashu-local/<object>`；Nginx 对已配置业务桶提供 GET/HEAD 媒体代理，支持视频 Range，拒绝写操作、管理路径和任意目标代理。当前上传返回 `host.docker.internal:9000`，局域网设备无法直接使用。历史本地绝对 URL 需通过受限兼容转换改为同源路径，云 OSS URL 保持原样。
- 其余基础设施服务继续绑定 `127.0.0.1`；局域网访问只开放 UI，不直接暴露数据库或管理端口。
- 验收分别检查本机 `http://localhost:8088`、本机 UI 的 API 代理和局域网另一台设备访问 UI；同时确认基础设施监听仍为 loopback。不可达时先检查 Windows 防火墙规则，不扩大数据库端口范围。

## 镜像与 Compose 管理

- 将 `aviggiano/redis-roaring:latest` 固定为本机已拉取并核实的 digest `sha256:a2679eb6c0fba5455e99e0aee8000700be33ee82ec7bd9ffaaeec29e29eb15e3`，或使用同 digest 的显式引用；验证 Docker 能按 Compose 配置解析和启动。
- 所有现用服务继续由当前 Compose 项目定义；工具型容器可保留 profile。
- 2026-10-18 实际容器盘点显示旧小哈书独立容器已移除；剩余 dtk、pgvector、searxng、redisinsight 等属于其他程序，不纳入本项目清理。后续若出现小哈书旧容器，只能在核实名称、端口、挂载和所属项目后单容器处理，保留卷；不根据“已停止”就判断无用。
- `Start-Local.ps1` 当前按固定容器名直接 stop 的行为也要收紧：先核实挂载/归属，再停止已确认的小哈书旧实例；遇到同名其他项目或无法判断的端口冲突就报告，不自动停止。

## 数据路径与可迁移性

- 为绑定挂载统一引入可配置的数据根目录，当前默认路径为 `F:\docker`；Compose 文件不再在每个服务中重复硬编码不同根路径。
- 路径预检和运行期配置生成脚本一并参数化，包括搜索词典、Redis 配置、Cassandra 配置和 FRP 日志。使用长语法 bind 并关闭 `create_host_path`，既有数据路径缺失时立即失败，避免拼错路径被自动建成空库目录。
- 生成的运行期配置放在 `infra/.runtime` 并加入本地忽略；密钥仍由现有 Compose 环境注入方式提供，示例文件只包含占位值。不得读取或写入项目根 `.evn`。
- 对现有 Docker 命名卷（特别是 MySQL）保留卷名和内容，不能直接切换到空目录 bind mount。MySQL 迁移到可移动目录前，先备份、执行显式恢复验证并获得单独确认。
- 外部卷名称也必须可配置，不能把当前机器的哈希卷名当作可移植默认。提供“复用既有数据”和“新机器显式初始化/恢复”两条入口；新机器通过显式本地配置准备凭据、配置和卷，不依赖已存在的旧容器。当前 `Prepare-Local.ps1` 只支持从旧容器/旧目录提取配置，不能直接作为全新机器安装器。
- README 说明怎样在另一台 Windows 主机设置数据根目录、检查路径挂载、恢复备份与启动 Compose。

## 备份与恢复

- 提供可重复执行的本地备份入口，输出到默认 `F:\docker\backups` 或显式配置的目录，并按时间戳分批存放，避免覆盖已有备份。
- 默认备份与数据在同一磁盘，只提供误操作/容器重建恢复能力；需要应对整盘损坏时把备份目标配置到另一磁盘或其他独立存储。
- MySQL 一致性导出明确包含 `xiaohashu`、`nacos_config`、`xxl_job`、`leaf` 的数据、结构及需要的程序对象，避免只恢复业务表却丢失注册配置、调度配置或 ID 分配状态；不复制运行中的 MySQL 数据文件代替一致性导出。
- Cassandra 采用指定业务 keyspace 的 flush 后命名 snapshot，将 SSTable、schema 和 manifest 实际复制出数据目录并校验；只在原目录创建硬链接 snapshot 不算完成备份。不跳过 flush，不混用在线数据目录作为隔离恢复目标。
- MinIO 镜像复制保存当前对象内容，并另存所需 bucket policy、配置和对象元数据；若启用版本历史，要明确当前 `mc mirror` 并不等价于完整版本备份。恢复验证包含对象内容、Content-Type 和业务桶读取权限。
- 同时保存必要的 `.runtime` 配置、部署版本、卷名映射及 ZooKeeper/Leaf 相关状态清单，含密钥的备份限制本地访问且不输出到日志或 Git。Canal 旧位点不能盲目用于重新导入的 MySQL；恢复后需按新 binlog 重建消费起点并重建 ES。
- 产物包含创建时间、来源、工具/镜像版本、退出码、文件清单和校验值；任一步失败不得写入整批备份成功标记。PowerShell 的 SQL/二进制输出不能经过会改变编码/字节的管道。
- Redis、ES 和搜索索引是否纳入快照单独标注：它们大部分可由权威源重建；如果备份 Redis 持久数据，作为辅助项而非 MySQL/Cassandra/MinIO 的替代品。
- 说明 RocketMQ 在途消息与不同存储的备份无法形成跨系统同一时间点的原子快照；不能把三份独立备份描述为严格一致。
- 提供恢复到隔离的本地测试服务/目录的演练步骤。演练不得覆盖当前运行数据；确认通过后才可安排实际恢复。
- 隔离恢复使用独立 Compose 项目、独立卷和网络，不引用现用 external 卷；端口不发布或选择独立端口。在线备份仅承诺各存储独立恢复点；需要较一致的本地恢复集合时，先阻止写入并处理完消息再取备份，不把各存储快照包装成原子事务。
- 不使用自动 prune，不删除旧备份；保留策略通过文档建议和人工复核确定。

## FRP 范围

FRP Compose profile 和本地转发配置保留。没有自有公网服务器的当前环境只验证本机隧道，不进行外网访问验收、不假定 VPS 地址，也不影响前端局域网访问验收。

## 验收场景

- `docker compose config` 对基础设施和应用组合解析通过；Redis 镜像解析为目标 digest。
- Compose 容器健康状态正常；前端 8088 可在局域网访问，API 代理正常；基础设施和网关端口保持 loopback。
- 局域网验收包含图片上传后显示、历史本地图片、头像和视频 Range，而非只打开首页；没有第二台设备时记录为未实测，不能拿本机访问主机 LAN IP 代替真正跨设备验证。
- 应用 TCP 健康探针只证明监听端口，业务 readiness 需用登录、发布/立即读正文、评论和搜索的必要路径确认，不能据 `healthy` 宣称全部业务正常。
- `docker inspect` 核对服务数据挂载。MySQL 仍使用原命名卷，其余路径挂载到配置数据根目录；容器重建后抽查数据仍在。
- 对随机命名的备份演练副本执行恢复验证，核对 MySQL/Cassandra/MinIO 数据可读；不触碰当前业务数据。
- 盘点旧容器并记录处理结果；任何单容器移除前必须确认挂载/依赖并保留数据卷。

## 明确延期与风险

- FRP 从公网服务器访问、VPS 配置与公网防火墙验收延期，直至用户有服务器。
- 将 MySQL 命名卷迁移到 `F:\docker` 会涉及真实业务数据迁移；本方案先保留既有卷，提供备份与迁移手册，不自动搬迁。
- 独立存储各自完成的本地备份不能取代跨存储事务备份。恢复后可能需要通过项目已有对账、消息补偿和索引重建流程收敛。
