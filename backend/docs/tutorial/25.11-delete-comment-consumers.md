# 25.11 MQ 消费者：评论删除后续业务开发

## 本节实现

- 新增广播模式的 `DeleteCommentLocalCacheConsumer`，异步清除评论服务本地详情缓存。
- 新增 `DeleteCommentConsumer`：删除一级评论时级联删除其二级评论，并更新笔记评论数；删除二级评论时递归删除回复、调整 Redis 子评论计数、刷新最早回复 ID，并发送评论热度更新消息。
- 为 `CommentLevelEnum` 增加按 code 查找枚举的方法，并补齐对应 MyBatis SQL。

## 验证

- JDK 17 下评论模块及依赖模块测试通过：40 项测试，0 失败、0 错误。
- 评论服务打包成功，并在 8093 端口启动；KV Feign 临时指向本机 18084 的测试服务。
- 使用随机 ID 调用 `POST /comment/delete`：一级评论连同 2 条二级评论删除，`t_note_count.comment_total` 和 Redis `commentTotal` 均由 3 降至 0。
- 使用随机 ID 删除二级评论：该评论及其回复从 MySQL 删除，父评论 `first_reply_comment_id` 更新为剩余回复；Redis `childCommentTotal` 从 3 降至 1，热度更新消息被消费者处理。
- 测试 MySQL 行和 Redis 键已清理；测试评论正文使用随机 UUID，Cassandra 删除请求成功返回。

## 为使教程逻辑生效而补充的修复

- `CommentDO` 的 `LocalDateTime` 字段标注 `yyyy-MM-dd HH:mm:ss`。实际 RocketMQ 消息采用此格式，默认 Jackson 解析会失败；新增回归测试覆盖该格式。
- `CommentDOMapper` 的主键查询列清单补上 `first_reply_comment_id`。原查询没有取出该字段，导致消费者无法判断删除项是否为最早回复；XML 映射回归测试已覆盖。

## 风险

- 教程在删除二级评论后只更新 Redis 的 `childCommentTotal`，没有同步更新 MySQL `t_comment.child_comment_total`。本次实测后 Redis 为 1、MySQL 字段仍为 3；这里按教程实现，未额外改写。
- 教程的 `selectByReplyCommentId` 返回单个 `CommentDO`。若一条评论存在多条直接回复，MyBatis 可能因结果不止一行而报错；本次验证覆盖的是单链回复。
