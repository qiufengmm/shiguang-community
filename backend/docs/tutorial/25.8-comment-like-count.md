# 25.8 计数服务：评论点赞数更新

## 本节实现

- 计数服务新增对 `CommentLikeUnlikeTopic` 的独立消费者组，使用 `BufferTrigger` 以 50,000 条缓冲上限、每批 1,000 条、最多等待 1 秒聚合消息。
- 新增点赞/取消点赞消息 DTO、计数 DTO 和操作类型枚举，按评论 ID 汇总 `LIKE` 的 +1 与 `UNLIKE` 的 -1。
- 评论计数 Hash 存在时更新 `likeTotal`；随后发送 `CountCommentLike2DBTTopic`，由入库消费者更新 MySQL 评论点赞数。
- 为 `CommentDOMapper` 增加按评论 ID 累加点赞数的 SQL。
- 教程要求 `like_total` 改为有符号字段；项目 DDL 和当前 Docker MySQL 表已是有符号 `BIGINT`，无需额外修改。

## 验证

- JDK 17 下 count-biz 本次运行的 13 项测试全部通过；项目既有 `MQTests` 按约定排除。
- Maven `-DskipTests package` 成功，计数服务运行于 8090，评论服务运行于 8093，两个评论计数消费者组均在线。
- 经真实接口调用点赞、取消点赞：Redis Hash 和 Docker MySQL 的 `like_total` 均按 `0 → 1 → 0` 变化；实际消息包含 `createTime`，DTO 解析正常。
- 测试后清除随机评论行、点赞行、Redis 计数 Hash 与 Bloom key，并复核均不存在。
- 除字段已符合要求而无需修改 DDL 外，本节遵循教程实现。
