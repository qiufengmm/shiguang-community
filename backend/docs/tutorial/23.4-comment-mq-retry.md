# 23.4 评论 MQ 发送重试

- 为评论 Biz 模块加入 Spring Retry 和 AOP 依赖，启用 `@EnableRetry`，并按教程最终方案配置 `RetryTemplate`、指数退避参数和 `taskExecutor` 线程池。
- 新增 `SendMqRetryHelper`：评论接口仍异步发送；异步回调失败后，把同步重发任务提交到线程池，最多执行 3 次，间隔按 1 秒、2 秒递增。超过次数进入兜底方法。
- `rocketmq.producer.retry-times-when-send-failed` 与 `retry-times-when-send-async-failed` 都设为 `0`，由自定义重试负责失败重试。
- 验证：JDK 17 下 `CommentServiceImplTest` 2 项通过，评论 Biz 打包成功；服务在 8093 启动并注册 Nacos。正常请求返回成功，RocketMQ 收到的消息包含随机测试 note、creator、reply ID 和时间；测试 Topic 已在验证后删除。
- 故障验证：仅把本次评论服务进程的 NameServer 临时覆盖为不可达地址，接口约 13ms 返回成功，后台日志确认异步失败后触发 3 次同步发送尝试，并进入兜底日志。随后已恢复服务使用 Docker RocketMQ，当前服务正常运行。
- **教程留有的可靠性缺口：**兜底方法仍是 `TODO`，没有将失败消息落库，也没有定时补偿任务。因此重试耗尽后消息仍会丢失；本节按教程不扩展实现，后续需要真正的补偿方案才能保证最终送达。
