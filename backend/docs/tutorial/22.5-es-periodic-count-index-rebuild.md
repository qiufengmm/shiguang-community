# 22.5 ES 索引计数定期更新：笔记、用户计数

- 将 `xiaohashu-search` 改为 Maven 父聚合模块，新增 `xiaohashu-search-api` 和 `xiaohashu-search-biz`；原搜索业务迁入 Biz，并按教程调整为 `com.quanxiaoha.xiaohashu.search.biz` 包。
- API 模块新增笔记、用户文档重建 DTO 和 `SearchFeignApi`。Biz 暴露 `POST /search/note/document/rebuild`、`POST /search/user/document/rebuild`，分别按 ID 查询 MySQL 并覆盖写入 ES。
- 数据对齐服务依赖 Search API，开启 Feign 扫描并新增 `SearchRpcService`；现有笔记点赞对齐 Job 在更新数据库计数后调用笔记文档重建。
- 验证：JDK 17 下搜索 Biz、数据对齐服务均打包成功。新搜索服务启动后原 `/search/ext/dict` 接口返回 200；两个重建接口由 RED 阶段的 404 变为成功，并通过随机用户、笔记和计数数据确认 MySQL 字段重建到 ES。临时 Spring 集成测试经 Nacos 发现 `xiaohashu-search`，由 `SearchRpcService` 调用两个 Feign 接口成功。临时测试行及 ES 文档已清理。
- **当前仓库缺少教程所说的其他计数 Job。** 对照 19 章教程和代码，仓库只有 `FollowingCountShardingXxlJob` 与 `NoteLikeCountShardingXxlJob`；没有笔记收藏、粉丝、笔记发布数 Job。`FollowingCountShardingXxlJob` 更新 `following_total`，而用户 ES 文档查询字段只有 `fans_total`、`note_total`，因此没有把用户文档重建错误地接到该 Job 上。`rebuildUserDocument` 的 Feign 接口和 RPC 方法已实现并验证，但现有定时任务尚未调用它；笔记收藏 Job 也未接入。
- **运行时观察：** 启动数据对齐服务时，RocketMQ 消费者在 `t_data_align_note_like_count_temp_20261016_2` 遇到已有记录重复插入的 Duplicate Key 异常；执行器仍正常启动，Feign 实测成功。后续应排查该临时表消费者的幂等处理。
