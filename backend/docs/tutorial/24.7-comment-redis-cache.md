# 24.7 评论分页查询：Redis 缓存

- 评论总数使用 Hash 缓存（`count:note:<noteId>`），数据库中没有计数行时抛出 `COMMENT-20001`；总数为 0 时直接返回。
- 热门一级评论前 500 条使用 ZSet（`comment:list:<noteId>`）缓存，详情 VO 使用 String Key（`comment:detail:<commentId>`）缓存。缓存未命中时仍从 MySQL、KV 和用户服务组装；详情失效时按 ID 回源并异步重建。评论总数、热点 ID 和详情均设置随机过期时间。
- 验证：JDK 17 下评论模块完整测试集 10 项通过并打包成功。服务真实发布随机根评论和回复，首次 `/comment/list` 回源后验证 Redis Hash、ZSet、详情及 TTL；相同请求再次成功返回缓存内容；删除单条详情缓存后请求成功回源并重建。MySQL、Cassandra 与相关 Redis 测试数据均已清理。
- 教程原样实现。沿用 24.6 的两个边界：用户 RPC 无结果时辅助方法会解引用空 Map；页面评论全为图片时 KV 批量查询会收到空 Key 列表（该 DTO 要求非空）。热点 ZSet 异步构建期间并发请求也可能同时回源，教程本节未加构建锁。
