# 22.6 修复增量笔记索引字段

- 按教程修改 `SelectMapper.xml`：封面取 `img_uris` 第一个链接并命名为 `cover`；作者昵称、头像分别命名为 `creator_nickname`、`creator_avatar`，与 `note` 索引 mapping 一致。
- 新增 `SelectMapperNoteIndexSqlTest` 检查生成 SQL 的三个字段表达式。修改前测试因旧字段名失败，修改后通过。
- 验证：JDK 17 下 `xiaohashu-search-biz` Maven reactor 打包成功。重启搜索服务后，调用 `POST /search/note/document/rebuild` 重建现有笔记 `2110936563180371999` 成功；ES `_source` 中 `cover` 和 `creator_nickname` 字段正确。该笔记的 MySQL `avatar` 本身为 `NULL`，因此 ES 没有保存 `creator_avatar` 字段；没有新增测试数据。
- **教程之外的遗留风险：** `NoteIndex.FIELD_NOTE_NICKNAME` / `FIELD_NOTE_AVATAR` 仍分别读取 `nickname` / `avatar`，而 ES mapping 及本节 SQL 使用 `creator_nickname` / `creator_avatar`。因此搜索响应中的作者昵称、头像仍可能为空。按本节教程仅修复 SQL，未改动搜索响应字段读取；后续若要修复，应统一 `NoteIndex` 与索引字段名。
