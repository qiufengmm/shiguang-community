# 24.1 计数服务：笔记评论总数更新

- 评论消费者先通过 KV 服务批量写入非空评论正文到 Cassandra，再在 MySQL 事务中批量写入评论元数据；只有 MySQL 插入行数大于 0 时，才异步发送 `CountNoteCommentTopic`。
- 计数服务按 noteId 聚合消息，使用 `INSERT ... ON DUPLICATE KEY UPDATE` 累加 `t_note_count.comment_total`。
- 验证：JDK 17 下 count/comment 相关单测 5 项通过，两个服务打包成功。直接调用评论发布接口两次，确认 MySQL 写入 2 条一级评论、Cassandra 保存 2 条正文、`t_note_count.comment_total=2`。随机测试记录已从 MySQL 和 Cassandra 清理。
- **教程源文件缺漏：**本地 23.8 正文与 23.7 重复，并在消费者代码处保留 Cassandra/MySQL 写入 TODO；24.1 正文却假设批量写库已完成。为使 24.1 的“写库成功后发送计数消息”逻辑可运行，本节同时补上了基于已有 KV 批量接口的正文保存和 MySQL 元数据批量插入。重试时 Cassandra 主键可覆盖同一条内容；跨 Cassandra/MySQL 的写入不在同一事务内，若 MySQL 持续失败可能留下 Cassandra 孤立正文，后续可按教程补偿机制处理。
