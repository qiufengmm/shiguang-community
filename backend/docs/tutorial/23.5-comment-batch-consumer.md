# 23.5 评论 MQ 批量消费

- 在根 POM 锁定 `rocketmq-client` 4.9.4（依赖树确认与 RocketMQ Spring Starter 实际传递版本一致），并在 comment Biz 中显式加入客户端依赖。
- 新增 `Comment2DBConsumer`，以 `DefaultMQPushConsumer` 集群模式订阅 `PublishCommentTopic`，消费组为 `xiaohashu_group_PublishCommentTopic`，单次消费上限设为 30；处理成功 ACK，异常返回 `RECONSUME_LATER`，并按教程保留批量写库 TODO。
- 新增计数服务模拟发送测试，发送 1,620 条带随机批次标识的消息，并等待全部异步发送回调结束。
- 验证：comment Biz 在 JDK 17 下打包通过；评论服务在 8093 启动，RocketMQ 注册信息显示 consumer 版本 V4_9_4、CLUSTERING、CONSUME_FROM_LAST_OFFSET。计数服务测试 1 项通过。RocketMQ 四个队列共收到并消费 1,620 条消息，消费积压归零；本次日志中的实际批次最大为 5，代码配置的上限是 30（实际批次随消息到达速度变化）。
- Topic 测试前不存在，消息验证后已删除 `PublishCommentTopic` 和本次消费组的 `%RETRY%` Topic；当前评论服务已恢复运行。
- **测试副作用：**教程里的 `@SpringBootTest` 启动了整个计数服务上下文，因而也运行了其他计数消费者；其中一条原有关注消息（user `672148930` → `908374217`）被消费，计数表中该用户的 `following_total` 当前为 1，而对应关系记录不存在。无测试前快照，无法安全判定原值，因此保留数据库现状；后续跑这个测试前应先确认计数服务的其他消费者不会处理待消费业务消息。
