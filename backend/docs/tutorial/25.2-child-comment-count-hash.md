# 25.2 一级评论：子评论总数更新与查询

- Count 服务为评论计数增加 `count:comment:<commentId>` Hash；二级评论聚合消费时，若一级评论计数 Hash 已存在，先原子增加 `childCommentTotal`，再更新 MySQL。
- Comment 服务分页读取时，从评论计数 Hash 取一级评论的子评论数、点赞数，以及首条回复的点赞数。计数 Hash 缺失时批量查 MySQL，并异步回填 Redis。
- 验证：JDK 17 下 count/comment reactor 单测通过（排除原有 `MQTests` 集成测试），两个模块打包成功。8093 `/comment/list` 实测通过 Redis Hash 命中和 MySQL 回源两条路径；回源后异步 Hash 回填成功。临时 MySQL、Redis 数据均已清理。
- 全量测试首次运行触发既有 `MQTests` 向评论主题发送 1620 条消息，broker 流控导致该测试失败；由此产生的 1619 条随机评论及对应计数行、Cassandra 正文已清理，RocketMQ 消费积压复核为 0。
- 按教程实现，没有功能性偏离。

## 教程实现风险

- 当前 `t_comment.like_total` 与 `child_comment_total` 列允许 `NULL`。教程在回填 Hash 时使用 `Map.of(...)`，若历史行的计数字段为 `NULL` 会抛 `NullPointerException`；首条回复点赞数读取也会对缺失值调用 `toString()`。本节保留教程写法。
- 24.8 已记录的本地 Caffeine 空值占位问题仍会影响同一评论页的后续请求：首次缓存未命中后，再查可能返回空列表。该问题不属于本节改动，未修改。
- 教程以 `RandomUtil.randomInt(5 * 60 * 60)` 设置过期时间，结果可能为 0，导致计数 Hash 立即过期。
