# 22.2 Spring Boot 3.x 整合 Canal Client

- 在父级 `pom.xml` 管理 Canal 1.1.7 的 `canal.client`、`canal.common`、`canal.protocol` 版本，并在搜索服务添加三个依赖。
- 在搜索服务 `application-dev.yml` 配置 Canal 地址 `127.0.0.1:11111`、destination `example`、订阅 `xiaohashu.t_note,xiaohashu.t_user` 和批量大小 1000。
- 新增 `CanalProperties`、`CanalClient`、`CanalSchedule`，由 `@EnableScheduling` 每 100ms 拉取并 ack Canal 批次；异常时按教程回滚。
- 验证：JDK 17 下 `mvn -pl xiaohashu-search -am -DskipTests package` 成功；搜索服务启动后 `/search/ext/dict` 返回 HTTP 200。对 `t_note` 的标题和 `t_user` 的昵称分别写入随机值，Canal 消费日志打印了两张表的 UPDATE 前后字段；随后将标题和昵称都恢复为原值，并以十六进制值确认恢复。
- 教程示例会打印整行 `t_user` 数据，其中含密码哈希和手机号。为严格跟随教程暂未改写打印逻辑；不要将这段日志用于生产环境，后续应过滤敏感字段。
- 初次启动消费者时，日志还打印了搜索服务启动前已经写入 binlog 的 `xxl_job_group` 更新记录；之后 `t_note`、`t_user` 的实时更新均正常消费。若要求启动后只处理订阅表，需确认历史积压已追平，或评估在 Canal 服务端配置表过滤。
