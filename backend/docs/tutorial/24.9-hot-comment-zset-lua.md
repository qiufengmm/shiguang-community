# 24.9 执行 Lua 脚本：更新热点评论 ZSet

- 评论写库后，按笔记分组，将一级评论批量写入已初始化且不足 500 条的热点 ZSet；评论热度写回 MySQL 后，再按笔记分组执行 Lua，更新 Redis 热度并在满 500 条时尝试替换最低分评论。`selectByCommentIds` 同时查询 `note_id`，供热度消息回写对应笔记的 ZSet。
- 验证：JDK 17 下评论模块 reactor 测试 14 项通过并打包成功。运行中的评论服务通过 `/comment/publish` 写入一级评论，ZSet 新增该评论且分数为 0；再发布二级回复，MySQL 一级评论的 `child_comment_total=1`、`heat=0.30`，Redis ZSet 分数从 0 更新为 0.3。随机测试评论、计数行、Cassandra 正文及 Redis Key 均已清理。
- 按教程原样实现，未擅自修正。隔离 Redis 实测发现教程更新脚本在 500 条边界有两处问题：更新 ZSet 已存在的成员时先删除最低分成员，再对已有成员 `ZADD`，会把基数从 500 降为 499；此外 Lua 将字符串类型的 `ARGV` 分数与 Redis 返回的字符串分数直接用 `>` 比较，数值 `10.00 > 9.99` 会被按字典序判为 false，未插入高分评论。
