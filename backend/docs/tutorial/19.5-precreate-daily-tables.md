# 19.5 预创建日增量表

`createTableJobHandler` 按明天的日期生成 yyyyMMdd 后缀，再按 `table.shards` 循环创建各个分片。默认 3 个分片，7 类表共 21 张。

| 表前缀 | 唯一标识 |
| --- | --- |
| t_data_align_following_count_temp | user_id |
| t_data_align_fans_count_temp | user_id |
| t_data_align_note_collect_count_temp | note_id |
| t_data_align_user_collect_count_temp | user_id |
| t_data_align_user_like_count_temp | user_id |
| t_data_align_note_like_count_temp | note_id |
| t_data_align_note_publish_count_temp | note_id，沿用本节教程 |

完整表名为 `<前缀>_<明天的日期>_<分片序号>`，分片序号从 0 开始。所有 DDL 使用 `CREATE TABLE IF NOT EXISTS`，重复执行保留已有表及数据。

## Nacos 配置

在命名空间 `xiaohashu`、分组 `DEFAULT_GROUP` 中使用 Data ID `xiaohashu-data-align-dev.yaml`，格式为 YAML。配置内容保存在 `infra/nacos/xiaohashu-data-align-dev.yaml`：

```yaml
table:
  shards: 3
```

配置采用 ASCII 内容，适配当前中文 Windows 与 JDK 17 环境。任务通过 `@Value` 读取分片数，并使用 `@RefreshScope` 接收 Nacos 动态更新。本地开发配置也保留同样的默认值。

## 调度与验证

将调度中心任务 1 的 Cron 改为 `0 0 23 * * ?`，在每天 23 点预建次日表。本节通过“执行一次”手动触发验证，演示调度保持停止（`trigger_status=0`）。

### 验证环境

- 执行器 AppName `xxl-job-executor-xiaohashu`，执行器端口 10001，自动注册地址 `http://host.docker.internal:10001/`，调度中心以容器内 `172.23.0.2` 访问宿主执行器。
- 服务监听端口应为 **8091**，启动前需清除环境变量 `SERVER__PORT` / `SERVER_PORT`。本机 shell 中存在非本项目使用的 `SERVER__PORT=64086`、`SERVER__HOST=127.0.0.1`，会干扰端口绑定。
- 验证过程中曾出现一次服务落在 8080 的现象，重启后恢复为 8091，**根因未定位，不能视为已修复**；每次启动后应先确认实际监听端口。

### 验证结果（2026-10-16）

调度日志中四次手动触发记录的 `trigger_code` 与 `handle_code` 均为 200：

| 验证项 | 触发记录 | 结果 |
| --- | --- | --- |
| 首次建表 | `xxl_job_log.id=6` | 生成 `_20261017_0/1/2` 共 21 张表，7 类前缀齐全 |
| 重复触发幂等 | `xxl_job_log.id=7` | 预先插入的随机记录保留，表数量仍为 21 |
| Nacos `shards` 3 → 2 | `xxl_job_log.id=8` | 日志精确出现 14 条建表语句，表名后缀仅 `_0`、`_1` |
| 恢复 `shards` 3 | `xxl_job_log.id=9` | 日志精确出现 21 条建表语句，`_0`、`_1`、`_2` 各 7 条 |

结构校验：每张表第二列（`user_id` / `note_id`）为 `bigint unsigned`，`id` 为 `bigint unsigned auto_increment`；`uk_user_id` / `uk_note_id` 唯一索引 `non_unique=0`；表 `ENGINE=InnoDB`、排序规则 `utf8mb4_unicode_ci`，中文表注释正常。

分片数的改动发生在同一服务进程内，未重启，`@RefreshScope` 接收 Nacos 更新后立即生效。建表语句条数按 MyBatis `Preparing:` 日志统计，未额外增加分片建表。

随机测试记录（`t_data_align_following_count_temp_20261017_0` 的 `user_id=1792145262`、`t_data_align_note_like_count_temp_20261017_2` 的 `note_id=1792145262`）已在验证后按唯一标识删除，两张表均回到 0 行；21 张次日空增量表保留供后续章节使用。
