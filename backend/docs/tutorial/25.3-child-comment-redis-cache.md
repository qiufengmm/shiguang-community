# 25.3 二级评论分页接口开发（2）—— 添加 Redis 缓存

- Comment 服务先从 `count:comment:<parentId>` Hash 读取二级评论总数；Hash 缺失时回源 MySQL 并异步回填。父评论不存在时返回 `COMMENT-20000`。
- 二级评论分页使用 `comment:childList:<parentId>` ZSET 缓存最早 60 条 ID，按时间戳升序；评论详情复用 `comment:detail:<commentId>`，点赞数从评论计数 Hash 读取。详情或计数缺失时回源 MySQL，并异步写回缓存。
- 一级评论和二级评论的评论计数 Hash 回源、评论详情批量写 Redis 逻辑已抽取复用。
- 验证：JDK 17 下 comment-biz 17 项单测通过；comment-biz reactor 打包成功。8093 `/comment/child/list` 用随机数据实测 MySQL 回源、异步初始化 ZSET、Redis 命中三条路径；父评论不存在时返回 `COMMENT-20000`。测试插入的 5 条 MySQL 评论和相关 8 个 Redis 键已清理。
- 按教程实现，没有功能性偏离。

## 教程实现风险

- Hash 回填沿用教程中的 `Map.of(...)`。`t_comment.like_total`、`child_comment_total` 列允许 `NULL`，历史数据若包含空计数字段，构建 Map 会抛 `NullPointerException`；本节保留教程写法。
- 若回复目标用户资料未查到，教程映射代码会直接调用 `replyUser.getNickName()`，可能抛出 `NullPointerException`；本节保留教程写法。
- 缓存未命中时先异步预热 ZSET，同时本次请求从 MySQL 返回；因此首个请求仍会走数据库，后续请求才有机会命中缓存。
