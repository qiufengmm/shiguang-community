# 23.8 MQ 消费者：评论批量写入（2）

- 按用户提供的 23.8 正文，消费者在 `TransactionTemplate` 中先批量写入 MySQL 评论元数据，再通过 KV Feign 批量保存非空评论正文；KV 失败时标记 MySQL 事务回滚并重试 MQ 消息。批量 SQL 使用 `INSERT IGNORE`，重复消费时忽略已存在的评论 ID。
- 正文和元数据的转换逻辑沿用 23.7 已有的 `CommentBO` 组装结果；正文空值仍由 KV RPC 服务过滤。
- 验证：JDK 17 下 `mvn -pl xiaohashu-comment/xiaohashu-comment-biz -am -Dtest=CommentDOMapperXmlTest -Dsurefire.failIfNoSpecifiedTests=false test` 通过；随后对 KV 与评论服务执行 `-DskipTests package` 并分别启动。通过 `/comment/publish` 发布随机评论后，确认 MySQL `t_comment` 保存了对应元数据，KV `/kv/comment/content/batchFind` 从 Cassandra 取回了相同正文。已通过 KV 删除接口删除 Cassandra 测试正文，按随机 `note_id` 清理 MySQL 行，并清除临时 Redis 测试键。评论消费者发出的计数通知由计数服务处理后，已删除对应的随机 `t_note_count` 行；RocketMQ 消费组积压恢复为 0。
- 为绕开原 Redis 容器因旧 AOF 中的 `R.SETBIT` 命令与当前 `redis:8` 镜像不兼容而启动失败的问题，本次验证使用了仅供测试的无持久化 Redis 容器（宿主机端口 16379）；原 Redis 数据目录未改动。
- **教程源文件异常：**本地教程目录的 23.8 Markdown 仍重复 23.7 正文。本节实现依据用户粘贴的 23.8 原文，不将重复的本地正文当作要求。
- **一致性风险（教程事务边界）：**`TransactionTemplate` 只能回滚本服务的 MySQL 事务；KV Feign 调用会写入远端 Cassandra，若远端成功而 MySQL 随后回滚，Cassandra 写入无法由本地事务撤销。实现遵循教程，不扩展分布式事务。
