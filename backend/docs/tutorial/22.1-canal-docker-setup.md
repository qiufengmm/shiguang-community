# 22.1 本地搭建 Canal 服务

- 复用现有 MySQL Docker 容器 `mysql8.0`，未按教程重建容器，避免覆盖其现有数据库与挂载数据。现场确认 `log_bin=ON`、`binlog_format=ROW`、`server_id=1`；`canal@%` 已有 `SELECT`、`REPLICATION SLAVE`、`REPLICATION CLIENT` 权限。
- 按用户要求将 Canal 部署为 Docker 容器，镜像 `canal/canal-server:v1.1.7`，名称 `canal-server`，映射宿主机端口 `11111`，容器重启策略为 `unless-stopped`：

  ```powershell
  $env:MSYS_NO_PATHCONV = "1"
  docker run -d --name canal-server --restart unless-stopped -p 11111:11111 `
    -e 'canal.instance.master.address=host.docker.internal:3306' `
    -e 'canal.instance.dbUsername=canal' `
    -e 'canal.instance.dbPassword=canal' `
    -e 'canal.instance.connectionCharset=UTF-8' `
    -e 'canal.instance.mysql.slaveId=2' `
    -e 'canal.instance.filter.regex=.*\..*' `
    canal/canal-server:v1.1.7
  ```

- 验证：容器状态为 `Up`，Canal 日志出现 `start successful` 并显示已连接 `host.docker.internal:3306`；MySQL `SHOW FULL PROCESSLIST` 中存在 `canal` 用户的 `Binlog Dump` 连接；本机 TCP `127.0.0.1:11111` 连通。
- 与教程的实现差异：教程通过 Windows 解压包启动 Canal；这里按用户要求改用 Docker。教程示例客户端消费并打印具体行事件，将在 22.2 整合 Canal Client 时验证。
