## 关键配置

`filter` 段把 MySQL 里的 `img_uris`（逗号分隔字符串）切成数组，取第一个元素作为 `cover` 字段，再移除 `img_uris`、`@timestamp`、`@version`；`output` 段用 `document_id => "%{id}"` 保证重复导入是覆盖而非追加。

`jdbc_driver_library` 与 `statement_filepath` 写的是 Windows 绝对路径，路径里含中文目录（教程路径）没问题，但改成不含空格的路径更省事。

## 索引查询 SQL

```sql
-- 笔记（infra/logstash/sync-es-note-index/jdbc.sql）
select n.id, n.title, n.topic_name as topic, n.type, n.img_uris,
DATE_FORMAT(n.create_time, '%Y-%m-%d %H:%i:%s') AS create_time,
DATE_FORMAT(n.update_time, '%Y-%m-%d %H:%i:%s') AS update_time,
u.nickname as creator_nickname, u.avatar as creator_avatar,
nc.like_total, nc.collect_total, nc.comment_total
from t_note n left join t_user u on n.creator_id = u.id
left join t_note_count nc on n.id = nc.note_id
where n.visible = 0 and n.`status` = 1
order by n.id

-- 用户（infra/logstash/sync-es-user-index/jdbc.sql）
select u.id, u.nickname, u.avatar, u.xiaohashu_id, uc.note_total, uc.fans_total
from t_user u left join t_user_count uc on u.id = uc.user_id
where u.`status` = 0 and u.is_deleted = 0
order by u.id
```

**与教程正文的唯一差异**：教程的笔记 SQL 直接写 `u.nickname, u.avatar`，但 20.9 定义的索引字段名是 `creator_nickname` / `creator_avatar`，对不上（结果里会出现 `nickname` 字段，索引里的 `creator_nickname` 反而为空）。教程自己在 SQL 前就提示「查询字段名需要和 es 索引中的字段名保持一致，不一致可通过 as 来重命名」，因此按该指引补了 `as creator_nickname` / `as creator_avatar`。
